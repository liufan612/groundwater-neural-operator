# Groundwater neural operators

Code for the head-conditioned two-stage groundwater flow and solute transport study, checked against `Manuscript_20261023.docx` and `Supporting_Information_20261023_lf.docx` on October 22, 2026.

The repository contains synthetic-data generation, five neural-network backbones, two-stage and dual-branch training, local flow/transport residuals, and the fixed numerical-model input configurations. Generated datasets and trained weights are produced locally by the commands below.

## Installation

Use Python 3.11. Install a CUDA-enabled PyTorch build appropriate for your GPU, then install this repository:

```bash
python -m pip install -r requirements.txt
python -m pip install -e .
```

`requirements.txt` records the main versions used for the local code checks. MODFLOW **6.8.0** is an external dependency; obtain it from the [USGS MODFLOW 6 releases](https://github.com/MODFLOW-ORG/modflow6/releases/tag/6.8.0). Set `MF6_EXE` to its executable:

```powershell
$env:MF6_EXE = 'C:\path\to\mf6.exe'
```

On Linux/macOS, use `export MF6_EXE=/path/to/mf6`. Training retains the original CUDA execution path. Run all commands from the repository root.

## Generate the baseline data

```bash
# Construct one model without launching the numerical solver.
python model/generate_dataset.py --build-only --scenarios dual_0

# Generate all 100 scenarios, aggregate outputs and fit training-only statistics.
python model/generate_dataset.py
```

The generator restores the prescribed coarse-domain inputs, samples the seeded conductivity fields, constructs the 20 m numerical grid and recorded vertical subdivisions, runs flow and transport, and exports the common 2 × 30 × 50 learning grid. It retains 30 saved states at 180-day intervals. The day-180 state initializes 29 autonomous forecast steps. The split is 70 training, 20 validation and 10 retained-test scenarios.

`configs/source_templates.zip` contains only fixed MODFLOW **input** configurations: geometry, initial/boundary conditions, stresses and material settings. Identical input texts are stored once and expanded by `model/template_inputs.py`. It contains no simulated trajectories. These fixed realizations preserve the paper's original forcing conditions; the conductivity realizations are generated by `model/random_k.py` using seed 20260908.

Generated datasets are written under `model/prepared_formal_mf680_randomk_r3_repaired/`. Raw solver outputs occupy considerably more disk space than this source repository. Model-input construction can be performed without the MODFLOW executable; numerical trajectories require it.

## Train the framework

The following commands use the paper's selected hyperparameters: AdamW, learning rate 0.0003, weight decay 0.000001, batch size 8, 5-step truncated backpropagation, at most 2,000 epochs, patience 100, and seeds 42/43/44.

```bash
# AFNO data-only and flow-guided head models.
python model/train.py head --model afno
python model/train.py guided-head

# Frozen-head, two-stage concentration models.
python model/train.py two-stage --group 00
python model/train.py two-stage --group C
python model/train.py two-stage --group H
python model/train.py two-stage --group HC

# Jointly trained dual branches without a predicted-head concentration input.
python model/train.py dual --group H
python model/train.py dual --group HC
```

| Group | Flow guidance | Transport guidance | Two-stage head prerequisite |
|---|---:|---:|---|
| 00 | 0 | 0 | data-only AFNO head |
| C | 0 | 0.001 | data-only AFNO head |
| H | 0.1 | 0 | flow-guided AFNO head |
| HC | 0.1 | 0.001 | flow-guided AFNO head |

Both routes project concentration onto the nonnegative physical domain. In the two-stage route, the head network is frozen during concentration training. In the dual route, transport-loss gradients are detached from head. Head selection uses validation head NRMSE; concentration and dual selection retain the original combined standardized head/concentration MSE criterion, with concentration NRMSE controlling early stopping.

Use `--seeds 42` to run one seed or `--epochs N` to change the training ceiling. Outputs are stored under `model/runs*/`. Completed runs are reused; an unfinished run resumes its `last.pt`. Start from a separate clean checkout to perform an independent repeat rather than reusing that directory.

## Five-backbone comparison

The available backbones are `unet`, `fno`, `afno`, `uno` and `deeponet`. The other four head models are independent; their concentration models all condition on the frozen AFNO head of the corresponding seed:

```bash
# Repeat these two commands for fno, uno and deeponet.
python model/train.py head --model unet
python model/train.py backbone-concentration --model unet
```

Train the data-only AFNO head first. AFNO concentration is the `two-stage --group 00` run. The entry point trains the final selected settings; it does not repeat the historical learning-rate search.

## Source-release cases

After baseline generation:

```bash
python model/generate_sources.py
# Additional matched-input intermittent cases used in Figure S2.
python model/generate_sources.py --arms intermittent
```

The four arms use the same 20 validation base scenarios:

| Arm | Timing | Concentration amplitude |
|---|---|---|
| S00 | continuous | baseline |
| S10 | pulse | baseline |
| S01 | continuous | elevated |
| S11 | pulse | elevated to match S00 total solute input |

The first period is common. Pulse input is active in zero-based periods 7–12 (days 1,260–2,340); water injection continues after solute input stops. Outputs appear in `model/prepared_source_arms/`. The source cases are development diagnostics, with no additional model training.

## Code checks

```powershell
$env:PYTHONPATH = "$PWD\src;$PWD\model"
python -m unittest discover -s tests -v
```

On Linux/macOS use `PYTHONPATH=src:model python -m unittest discover -s tests -v`. The CUDA tests exercise the five concentration backbones and both recurrent training routes. CPU tests exercise local balance, boundary conditions and early stopping.

## Limitations and release status

The paper's original forcing realizations are distributed as fixed input configurations because the available older notebook does not establish an exact regeneration of those realizations from a recorded random seed. The numerical solutions are generated afresh.

Local equation residuals are approximate learning-grid diagnostics. They are distinct from the numerical simulator's cell-budget acceptance check. The retained-test split had been used earlier in the project; source-release diagnostics are based on validation scenarios. The original checkpoint-selection and unequal realized training budgets are preserved.

This is a source-code preparation, not a new numerical or training experiment. Full 100-scenario regeneration and 2,000-epoch training were not rerun during packaging. See the reproduction notes for the checks actually completed. A publication DOI and repository license have not yet been assigned; the authors should select the license before public release.

The training commands report validation metrics. They do not run the manuscript's retained-test evaluation, source-case inference, SHAP or figure-production pipeline. The historical learning-rate search and physics-weight/scale selection are represented by their final selected settings.
